# 미션 18 서비스 구상

영화 정보 · 리뷰 · 리뷰 감성 분석 웹 애플리케이션의 **구상 문서**다.
확정된 설계 결정을 서술하며, **작업 순서와 진행 상태는 다루지 않는다** —
그쪽은 [PROJECT_PLAN.md](../plan/PROJECT_PLAN.md)가 유일한 기준이다.
구조도 · ERD · 주요 흐름 도식은 [architecture.md](../plan/architecture.md)에 있다.

최초 9단계 구상은 가이드 요건과 대조하는 과정에서 여러 항목이 바뀌었다.
원안은 이 문서 `H. 원안 기록`에 남겨둔다.

## A. 서비스 개요

### A-a. 목적

스프린트의 마지막 미션으로, 프론트엔드 · 백엔드 · 모델 서빙을 하나의 서비스로 통합한다.
미션 17이 Streamlit 단일 앱 + ONNX 추론이었다면, 미션 18은 여기에
백엔드 분리 · DB · REST API가 더해진 3-tier 구성이다.

### A-b. 구성

```
[Streamlit]  ──HTTP──>  [FastAPI]  ──>  [SQLite: 영화 / 리뷰]
   화면만                 데이터 소유         │
                                        [ONNX 감성 분석 모델]
```

모든 데이터는 백엔드가 소유한다. Streamlit 쪽에는 별도 저장 기능
(로컬 파일 · 세션 영속화 등)을 두지 않는다 — 가이드에 명시된 제약이다.

## B. 데이터

### B-a. 데이터 소스

크롤링 계획은 폐기했다. 두 개의 공식·공개 소스를 쓴다.

| 대상 | 소스 | 비고 |
|---|---|---|
| 영화 메타데이터 | **TMDB API** | 출처 표기 의무 있음 |
| 리뷰 | **NSMC** (네이버 영화 리뷰 20만 건) | 필드는 `id / document / label` |

#### B-a-1. TMDB

감독은 `/movie/{id}` 응답에 없다. `/movie/{id}/credits`의 `crew`에서
`job == "Director"`를 추출해야 한다. 포스터는 `poster_path`를 이미지 CDN 베이스와
조합해 **URL만 저장**하고 이미지 파일은 저장소에 두지 않는다.

수집은 로컬에서 1회 실행해 DB에 적재하고 적재본만 배포한다.
이렇게 하면 런타임에 API 키가 필요 없다.

#### B-a-2. NSMC

TMDB 리뷰를 쓰지 않는 이유는 두 가지다. 대부분 영어라 한국어 모델에 넣을 수 없고,
영화당 편수가 적어 "각 영화당 리뷰 10건 이상" 캡처 요건을 채우지 못한다.

NSMC에는 대상 영화 정보가 없으므로 **리뷰-영화 대응은 임의 배정**이다.
실제 그 영화의 리뷰가 아니라는 사실을 보고서에 명시한다.
제목 · 작성자 · 등록일도 NSMC에 없어 파생 생성한다.

### B-b. 데이터 모델

| 영화 | 리뷰 |
|---|---|
| ID | ID |
| 제목 | 작성자 |
| 개봉일 | 영화 ID (FK) |
| 감독 | 제목 |
| 장르 | 내용 |
| 포스터 URL | `created_at` |
| `external_rating` | `sentiment_label` |
| `tmdb_id` | `sentiment_score` |
| | `model_version` |
| | `confidence` |

- `created_at`은 "최근 10개 리뷰" 화면과 페이지네이션 정렬 기준이라 생략할 수 없다.
- `model_version`은 모델 교체 시 과거 점수와 기준이 달라져 평균이 오염되는 것을 막는다.
- `confidence`는 저확신 예측을 화면에 표기하기 위한 값이다. 보정 로직에는 쓰지 않는다.

### B-c. 평점 2종

두 평점은 **성격이 다른 별개 필드**다. 한 필드에 담으면 서로 덮어쓴다.

| 필드 | 출처 | 범위 |
|---|---|---|
| `external_rating` | TMDB `vote_average` 수집값 | 0 \~ 10 |
| `sentiment_rating` | 소속 리뷰 감성 스칼라의 산술평균 (파생값) | -1 \~ +1 |

감성 스칼라는 `부정 -1` / `중립 0` / `긍정 +1`이다.
화면에는 **0\~5 별점으로 환산**해 표시한다 — `(x + 1) / 2 * 5`.
환산은 표현 계층에서만 수행하고 DB와 API 응답은 원값을 유지한다.

## C. 감성 분석 모델

미션 13에서 만든 자산을 재사용한다. 처음부터 새로 학습하지 않는다.
경로는 미션 18 폴더(`missions/mission18/`) 기준이다.

```
../mission13/CheckPoint/modelA_full_ft.onnx (+ .onnx.data, 합계 약 128MB)
../mission13/vocab_for_onnx/               # tokenizer.json · vocab.txt
```

### C-a. 사양

ELECTRA 계열 경량 모델(hidden 256 · 12 layers · vocab 54,343), 3-class 분류.
`좋아요 / 보통 / 별로에요` 3단 표기와 클래스 수가 맞는다.
`id2label`이 `LABEL_0~2`이므로 어느 인덱스가 어느 감성인지 미션 13 노트북에서
확인해 고정한다. 추정으로 매핑하지 않는다.

### C-b. 제약

- `.onnx`와 `.onnx.data`(external data)는 짝이며 분리하면 로드에 실패한다.
- Fixed Shape이라 입력 시퀀스 길이가 export 시점 값으로 고정된다.
  리뷰가 길면 truncation, 짧으면 padding이 필수다.
- 미션 13 ONNX를 그대로 쓴다. 재-export하지 않는다.

### C-c. 도메인 이동

미션 13의 학습 도메인은 쇼핑몰 · SNS 리뷰인데 본 미션의 추론 대상은 영화 리뷰다.
성능 저하 가능성이 있으므로 NSMC 정답 라벨로 실측하고 그 결과를 보고서 논점으로 삼는다.
가이드가 요구하는 "모델 경량화 고민" 항목은 미션 13의
Full FT / Freeze / LoRA-PEFT 비교 결과로 서술한다.

### C-d. 저확신 예측

추론은 **리뷰 등록 시 1회**만 수행하고 결과를 저장한다.
조회 시마다 추론하면 목록 10건당 10회 추론이 발생한다.

`confidence`(= `max(softmax(logits))`)가 낮은 예측은 화면에 `판정 애매` 등으로 표기한다.
추가 의존성도 지연도 없이 모델의 불확실성을 사용자에게 전달하는 방법이다.
Vector DB를 이용한 kNN 보정은 검토했으나 **도입하지 않는다** —
미션 18에 검색 · RAG 요건이 없고, 하이퍼파라미터 · 인덱스 영속성 · 이웃 라벨 편향 관리
부담이 평가 대상이 아닌 곳에 붙는다. 필요 근거는 NSMC 성능 실측 이후에 판단한다.

## D. 화면 구성

가이드의 필수 / `심화` 구분을 따른다. `심화`는 선택이지만 본 구상은 수행을 전제한다.

| 화면 | 내용 | 구분 |
|---|---|---|
| (홈) 영화 목록 | 포스터 + 그 아래 제목 병기, 평균 평점 | 필수 |
| 영화 추가 | 제목 · 개봉일 · 감독 · 장르 · 포스터 URL 입력 | 필수 |
| 영화 상세 | 상세 정보 + 리뷰 목록 (10개씩 페이지네이션, 3단 감성 표기) | `심화` |
| 리뷰 등록 | 영화 선택 · 작성자 · 제목 · 내용 | `심화` |
| 최근 리뷰 | 전역 최신 10개 (영화 ID · 등록일 · 내용 · 감성 결과) | `심화` |

영화 삭제는 필수 API이므로 화면에도 진입점을 둔다.
TMDB 출처 표기를 화면 하단에 넣는다.

## E. 백엔드 구성

| 구분 | 엔드포인트 |
|---|---|
| 필수 | 영화 등록 / 전체 조회 / 단건 조회 / 삭제 |
| `심화` | 리뷰 등록 / 영화별 조회 / 삭제 |
| `심화` | 최근 리뷰 조회, 평점 조회(감성 스칼라 평균) |

- 페이지네이션은 `limit` / `offset` + 전체 건수 반환. 정렬은 `created_at` 내림차순.
- 예외 처리: 404(없는 영화), 422(입력 검증 실패),
  추론 실패 시 리뷰는 저장하되 감성을 null로 두고 평균 계산에서 제외한다.
- FastAPI Docs 전체 캡처가 제출물이므로 모든 엔드포인트에
  `summary` / `description` / 응답 모델을 채운다.

## F. 배포 구조

```
[Streamlit Community Cloud]  ──HTTPS──>  [Cloud Run: FastAPI + ONNX + SQLite]
        (제출용 public repo)                        (동일 컨테이너)
```

- Vercel은 Streamlit을 구동할 수 없다(서버리스, 상시 프로세스 · WebSocket 불가).
- 백엔드는 Cloud Run. 메모리를 1GiB로 지정할 수 있다.
  Render 무료 티어는 512MB 고정이라 ONNX 128MB + onnxruntime + 토크나이저 + FastAPI
  조합에 빠듯하다(추정 피크 400\~600MB).
- Cloud Run의 컨테이너 파일시스템은 인메모리라 SQLite 쓰기가 메모리를 잠식하고,
  인스턴스 교체 시 데이터가 사라지며, 인스턴스가 2개 이상이면 각자 다른 DB를 본다.
  → 시드 데이터를 이미지에 굽고 `--max-instances=1`로 고정한다.
  배포본은 데모용이며 영속 저장은 로컬 실행 기준임을 보고서에 명시한다.
- 모델은 `lifespan`에서 1회 로드 후 재사용한다.
- 백엔드 base URL은 `localhost` 하드코딩 금지 — 환경변수 / `st.secrets` 주입.
- 아카이브 저장소는 private을 유지하고, **제출 코드만 담은 별도 public 저장소를 신설**한다.

## G. 제출물

```
mission18/3팀_신호정_미션18/
├── (보고서 PDF)
└── (코드) — frontend/ 와 backend/ 로 분리
```

동작 캡처는 **영화 3개 이상, 각 영화당 리뷰 10개 이상**이 요건이다.
리뷰 목록이 10개 단위 페이지네이션이므로 시드 수량을 여기에 맞춘다.

보고서에 반드시 넣을 항목은 다음과 같다.

- TMDB 출처 표기
- NSMC 리뷰-영화 대응이 임의 배정이라는 사실
- 배포본 SQLite의 비영속성
- 도메인 이동에 따른 모델 성능 변화, confidence 구간별 정확도

## H. 원안 기록

최초 9단계 구상이다. 아래 항목들이 이후 변경되었으므로 **참고용 이력**으로만 본다.
변경 내역과 사유는 [PROJECT_PLAN.md](../plan/PROJECT_PLAN.md)의 '`mission-concept.md` 대비 변경점'에 있다.

1. 영화 정보를 수집할 웹 크롤링 도구를 선정한다. → **폐기, TMDB API로 대체**
2. 영화 정보를 수집해 영화 데이터를 생성한다.
   - 구조: ID / 제목 / 개봉일 / 감독 / 장르 / **평점** / 포스터 URL
   - → 평점이 수집값과 감성 평균으로 **분리**되었고 `tmdb_id`가 추가되었다
3. 리뷰 데이터를 구성한다.
   - 구조: ID / 작성자 이름 / 참조 영화 ID / 제목 / 내용
   - → **NSMC로 확정**. `created_at` · 감성 결과 · `model_version` · `confidence` 추가
4. 리뷰 감성 분석에 필요한 모델(+경량화)을 선정한다. → **미션 13 자산 재사용**
5. 프론트엔드 화면을 기획한다.
   - (홈) 영화 목록 / 영화 추가 / 영화 상세 + 리뷰 표기
   - → **리뷰 등록 화면과 최근 리뷰 화면이 누락되어 신설**
6. 백엔드 구성을 기획한다. (영화 DB CRUD, 제목·별점 조회, 리뷰 DB CRUD)
7. 위 요소들을 조합할 구조를 기획한다. → **배포 토폴로지 포함으로 확장**
8. 기획대로 구현한다.
9. 구현된 기능의 작동을 검증한다.

원안은 **수집 → 기획** 순서였으나, 스키마가 화면 · API 계약보다 먼저 확정되면
기획 과정에서 드러나는 누락 필드 때문에 재수집이 발생한다(실제로 `created_at`과
감성 결과 필드가 누락되어 있었다). 그래서 **계약을 먼저 고정하고 수집을 뒤로** 옮겼다.
